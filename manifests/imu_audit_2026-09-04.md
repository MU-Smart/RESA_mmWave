## Anomalies and Red Flags

### No Critical Issues Detected ✓

1. **Cadence stability**: All sessions show perfect, zero-jitter timing. No anomalous spikes or drops in inter-sample intervals.
2. **Monotonicity**: All timestamp streams strictly monotonic; no duplicates, gaps, or resets.
3. **Gravity magnitude**: All sessions within reasonable bounds (mean 9.8-10.4 m/s²). One session has wider transient range (3.87-20.81 m/s²) consistent with active motion, not sensor malfunction.
4. **Recorder consistency**: Single recorder version across all analyzed sessions; no version drift or heterogeneous recording schemes.
5. **Timing metadata**: `hw_to_wall_offset_ms` values stable and plausible (-120 to -192 ms typical for D435i USB lag).

### Minor Observations (Not Blockers)

- **Session 2026-07-20_18-40-56** shows larger gravity magnitude range (3.87-20.81 m/s²), suggesting the capture included significant motion or acceleration transients. This is **not a data quality issue**, just a note that this session may be more useful for motion calibration than for stationary gravity-reference validation.
- **`hw_to_wall_offset_ms` variation** (~70 ms peak-to-peak) is expected and reflects per-session USB timing variability. No single outlier requires investigation.

---

## Recommendations for Calibration Pipeline

1. **Proceed with IMU-assisted calibration** using the 644 sessions from `ds_buildingunknown_2026-07-20`. Data quality and consistency are excellent.

2. **Legacy datasets (ds_legacy_dataset2, dataset3, McVey)** have no IMU coverage and should **not** be included in the IMU-assisted pipeline. These sessions can still be used for radar-camera (non-IMU) calibration if needed.

3. **Validate IMU playback** in the calibration pipeline on at least one session from each temporal sub-region of the `ds_buildingunknown_2026-07-20` group (e.g., early July, late July, late August) to confirm the pipeline handles the stable cadence and timestamp format correctly.

4. **`hw_to_wall_offset_ms` handling**: The observed ~70 ms variation across sessions should be **preserved per-session** in the calibration (read from `meta_data.json` for each session) rather than using a group-level constant. This ensures accurate synchronization between IMU, camera, and radar timestamps.

5. **Motion filtering**: Session 2026-07-20_18-40-56 with wide gravity range is suitable for **dynamic calibration** validation; sessions with tighter gravity clustering (e.g., 2026-07-21_16-37-19) are suitable for **static gravity reference** validation.
